## 1. 데이터 탐색 및 클래스 분포 (CP-01)

- **데이터 크기:** 12330행, 18열
- **결측값 및 중복 행:** 125행   
  - 중복 행을 삭제하지 않은 이유:    
    -웹사이트 이용 로그 특성상 동일한 패턴의 정상적인 유저 행동이 존재할 수 있음  
    -시스템 오류로 인한 중복 적재였다면 빈도수가 훨씬 높았을 것으로 판단하여, 데이터 손실을 방지하고자 중복 행을 삭제하지 않고 그대로 유지함
    
- **수치형 특성 분포의 특징(`ProductRelated`, `PageValues` 등):**  
    - ProductRelated, ProductRelated_Duration, PageValues는 대부분의 세션이 작은 값에 몰리고 일부 세션에서 매우 큰 값이 나타나는 우측 편향 분포이며, PageValues는 특히 0에 집중됨
    - 컬럼마다 값의 범위가 크게 달라 스케일링이 필요하고, 큰 값(이상치)의 영향도 고려해야 함

- **구매(`Revenue=1`) 건수와 비율:** 1,908건 / 15.47%
- **미구매(`Revenue=0`) 건수와 비율:** 10,422건 / 84.53%  

### **분석:**  모두 미구매로 예측했을 때 Accuracy가 약 84.53%인 이유와 이 수치만으로 평가하기 어려운 점을 작성합니다.
- 전체 방문 12,330건 중 구매는 약 15.47%뿐이고 84.53%는 구매 없이 끝나서, 모든 방문을 미구매로 예측해도 Accuracy가 약 84.53%가 된다
- 하지만 이 모델은 구매 고객을 하나도 찾지 못해 구매 Recall이 0이므로, 높은 Accuracy가 좋은 모델을 뜻하지 않는다
- 비구매가 구매보다 약 5.5배 많은 불균형 데이터라서 Accuracy만으로 평가하기 어렵다
- 그래서 Precision, Recall, F1-score 등 구매 클래스 중심의 지표로 평가한다
- 구매 데이터가 적기 때문에, 학습할 때 구매 쪽 오답에 더 큰 벌점을 주는 방법(클래스 가중치)도 함께 고려한다

## 2. 계층화 데이터 분할 (CP-02)

- **Train:** 8,630건 / 구매 비율 15.48%
- **Validation:** 1,850건 / 구매 비율 15.48%
- **Test:** 1,850건 / 구매 비율 15.48%
- **`stratify`를 적용한 이유:** 
    - stratify(계층화)는 데이터를 나눌 때, 정답(클래스) 비율을 나눈 묶음마다 똑같이 맞춰 주는 옵션
    - 구매가 약 15%뿐인 불균형 데이터라서, 랜덤으로 나누면 세트마다 구매 비율이 달라질 수 있다.
    - 모두 구매 비율을 약 15.48%로 같게 맞춰 평가를 공정하게 하기 위함이다.
- **1일차 회귀의 날짜 순서 분할과 다른 이유:**
    - 1일차는 시간 순서가 있는 데이터라 미래 정보가 학습에 섞이지 않도록 날짜순으로 나눴다
    - 이번 데이터는 세션 한 건 한 건이 독립적이라 날짜 순서보다 구매 비율을 맞추는 것이 중요해 계층화 랜덤 분할을 사용했다.

### **분석:** Train·Validation·Test의 구매 비율이 유사한지 확인하고 의미를 1~2문장으로 작성합니다.  

| 데이터셋 | 행 수 | 구매 비율 |
|---|---|---|
| Train | 8,630 | 15.48% |
| Validation | 1,850 | 15.46% |
| Test | 1,850 | 15.46% |

- 데이터를 약 70% / 15% / 15%로 나눴고, 세 세트 모두 구매 비율이 약 15.5%로 거의 같다
- 계층화 분할(stratify) 덕분에 Validation과 Test도 Train과 같은 구매 비율을 가져, 모델을 공정하게 평가할 수 있다

## 4. 데이터 전처리 및 PyTorch 입력 준비 (CP-03)

- **범주형 특성(One-Hot 인코딩):** Month, OperatingSystems, Browser, Region, TrafficType, VisitorType (6개)

- **수치형 특성(표준화):** Administrative, Administrative_Duration, Informational, Informational_Duration, ProductRelated, ProductRelated_Duration, BounceRates, ExitRates, PageValues, SpecialDay (10개)

- **이진 특성(변환 없이 사용):** Weekend (1개)

- **숫자로 표현된 코드값(`OperatingSystems`, `Browser` 등)을 범주형으로 처리한 이유:**  
  - 숫자의 크기나 순서가 아니라 종류를 구분하는 번호임
  - 그대로 쓰면 모델이 3이 1보다 크다고 잘못 해석할 수 있음
  - 원-핫으로 종류별 0/1 컬럼으로 펼쳐 이를 막음

- **`handle_unknown="ignore"`를 설정한 이유:**
  - Train에 없던 값이 Validation/Test에 나와도 에러 없이 모두 0으로 처리함
  - 전처리가 중간에 멈추지 않게 하기 위함

- **Train 전처리 전후 Shape:** (8630, 17) → (8630, 73)  컬럼수 늘었음

- **Validation에 적용한 변환 기준:**  
  - Train으로만 학습(fit)한 평균, 표준편차, 범주 목록을 그대로 사용해 transform만 적용함
  - Validation 정보가 전처리에 섞이지 않게 하기 위함

- **PyTorch 입력·타깃 Tensor의 자료형 및 Shape:**  
  - 입력: float32 (8630, 73)   세션 8,630개, 각 세션의 특성 73개
  - 타깃: float32 (8630, 1)    세션마다 정답(구매 여부 0/1) 1개

- **`DataLoader` 배치 크기와 배치 수:** 
  - 256(배치 크기) / 34(배치 수)
  - 8,630개를 한꺼번에 학습하지 않고 256개씩 묶어서 학습한다는 뜻입

### **분석:**  신경망 입력을 `float32` Tensor로 준비하고 미니배치를 만드는 이유를 1~2문장으로 작성합니다.  
- 신경망의 가중치가 기본적으로 float32이므로, 입력과 정답도 float32 Tensor로 맞춰 변환함
- 256개씩 묶은 미니배치(34개)로 학습하면 한 건씩 학습할 때보다 가중치 갱신이 안정되고 계산도 빠름
