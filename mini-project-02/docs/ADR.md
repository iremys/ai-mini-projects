## NLP — BERT 기반 한국어 의미 검색 시스템 개발 및 성능 비교

### 의사결정 ① 활용 목적과 우선 평가 지표 선택 (CP-07~CP-09)

**문제**

검색 시스템의 활용 목적에 따라 첫 번째 검색 결과의 정확성, 상위 후보에 정답이 포함되는지, 정답 문서의 순위 중 무엇을 더 중요하게 평가할지 결정해야 합니다.

- **가정한 활용 상황(`USE_CASE`):**  
`책 관련 키워드만 입력하면 띄어쓰기·오타가 있어도 GPU 없이 찾아주는 도서 검색기`
- **검토한 지표:** Hit@1, Recall@3, MRR@5
- **최종 우선 평가 지표(`PRIORITY_METRIC`):** `(MRR@5)`
- **선택 근거(사용자가 검색 결과를 어떻게 활용하는지):** 
  - `정확한 서지 정보 대신 기억나는 키워드 위주로 검색하는 상황임`
  - `질의마다 찾는 책은 한 권이지만, 사용자는 검색 목록을 위에서부터 훑어보며 원하는 책을 직접 고름`
  - `찾는 책이 검색 목록의 위쪽에 뜰수록 사용자가 더 빠르게 골라낼 수 있음`
  - `상위 5개 내 정답의 순위까지 점수에 반영하는 MRR@5가 이 활용 방식에 가장 적합함`
- **함께 고려할 다른 지표 또는 제약:**  
  - `보조 지표 (Recall@3): 상위 3개 후보 안에 찾는 책이 포함되는 질의의 비율을 함께 확인함`
  - `보조 지표 (Hit@1): 정답 도서가 1위인 질의의 비율을 참고함`


**분석 근거:** `02_nlp_model_analysis.md`의 2~4절

### 의사결정 ② 최종 검색 방식 선택 (CP-09)

**문제**

문자 기반 TF-IDF, 일반 BERT의 Mean Pooling, Sentence-BERT 검색 방식의 성능과 특성을 비교하여 최종 검색기를 선택해야 합니다.

- **비교한 선택지:** TF-IDF / BERT / Sentence-BERT
- **최종 선택한 검색 방식(`SELECTED_METHOD`):** `tfidf` 
- **선택 근거(`SELECTION_REASON`, 실제 Validation 수치와 검색 실패 사례를 활용):**   
  - 우선 지표인 MRR@5에서 TF-IDF가 0.917로 SBERT(0.821)와 BERT(0.759)를 크게 앞섬
  - Hit@1(0.883)과 Recall@3(0.967)에서도 TF-IDF가 세 방식 중 가장 높은 성능을 기록함
  - 일반 BERT는 문장 유사도 목적의 추가 학습이 없어(Hit@1 0.667, Recall@3 0.833) 전반적인 순위 성능이 가장 낮음
  - 이순몽(QV014)·오브스테트릭스(QV019) 같은 고유명사,희귀어가 포함된 질의에서는 문자 2~3-gram 기반 TF-IDF가 정확한 표현 매칭에 유리함
  - 반면 질문과 문단의 문자 겹침이 적고 표현이 달라지는 질의에서는 TF-IDF가 약하고 문장 의미 관계를 학습한 SBERT가 상대적으로 유리한 경향을 보임

- **트레이드오프(다른 방식과 비교해 얻은 장점과 감수한 단점):**  
  - **얻은 장점:**
    - 세 방식 중 가장 높은 검증성능(MRR@5 0.917) 확보
    - 문자 2~3-gram 적용으로 띄어쓰기 차이나 단어 일부만 입력한 경우에도 부분 일치를 잘 잡아냄
    - GPU 없이 CPU 환경에서도 임베딩 계산 부담 없이 빠르고 가볍게 운영 가능함
  - **감수한 단점:**
    - 문맥과 의미 관계를 반영하는 SBERT와 달리, 유의어나 풀어쓴 설명처럼 글자 겹침이 적은 질의에서는 검색 성능이 떨어짐
    - 단순 문자 빈도,IDF 기반이므로 문맥적 의미 추론이나 다의어 구분은 어려움

- **추후 확인할 점(실제 사용 데이터, 검색 처리 비용 등):**    
  - **데이터 도메인 및 규모 차이**
    - 현재 테스트는 KLUE-MRC 문단 200개·검증 60개에 한정됨
    - 실제 책 제목·저자·출판사·소개글 데이터로 성능 재검증 필요
  - **실제 사용자 질의 패턴 차이**
    - 테스트 질의와 다른 실제 사용자의 오타,줄임말,띄어쓰기 오류 대응력 확인 필요
    - 키워드 외에 유의어나 줄거리 검색 비중이 높아질 경우 품질 저하 점검 필요
  - **실서비스 확장 시 처리 비용**
    - 도서 수 증가에 따른 전체 문서 코사인 유사도 계산 속도 확인 필요
    - `max_features=30000` 적정성 점검 및 필요 시 SBERT 결합(하이브리드) 검토
